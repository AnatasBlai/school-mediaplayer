# Задача 15. Автотесты чистых функций (`npm test`)

Сейчас всё проверяется скриншотами. Логика звонков, правил «Когда», импорта из Excel и разбора списков — чистые
функции без Vue, их легко покрыть тестами. Тогда следующая правка не сломает незаметно, например, перемены.

## Как должно работать

- Папка `tests/`, файлы `*.test.js`, встроенный раннер Node: `node:test` + `node:assert/strict`. **Никаких новых
  зависимостей.**
- В `package.json` скрипт `"test": "node --test tests/"`. Запуск `npm test` — все тесты зелёные, вывод короткий.
- Даты в тестах — только локальные `new Date(2026, 9, 19, 9, 0)` (месяц с 0), не строки ISO: функции работают
  по местному времени.

## Что покрыть (минимум)

- `src/bells.js`: `parseBells` (разделители `-–—`, `8.00`, мусорные строки), `bellsForDay`, `bellStatus` — все
  `kind`: none (maxLesson 0), before, lesson (+ `left`), break, after; лишние звонки сверх `maxLesson` не считаются;
  `plural` (1, 2, 5, 11, 21, 112).
- `src/rules.js`: `ruleState` — даты включительно, «по» раньше «с», дни (воскресенье = 7), время [from, to),
  интервал через полночь, `breaks` с подставным `isBreak`; `isBlanked` (пустой период не гасит); `rulesText`
  (Пн–Пт, выходные); `tickerTexts` (until включительно, выключено → []); `countdownState` (без времени — весь день,
  со временем — до минуты, `days`, `over`).
- `src/scheduleImport.js`: `splitTable` (ячейки в кавычках с переносом, `""`), `parseClassName` (латиница «5A» →
  «5А», пробелы), `parseLesson`, `parseScheduleTable` на маленькой таблице.
- `src/winners.js`: `parseLine` «8А Иванов Иван», `winnerScreens` — сколько экранов при разном числе призёров.
- `src/deckText.js`: `parseCards` → `cardsToText` → `parseCards` даёт то же (без id).
- Сервер: экспортировать (без изменения поведения) `cleanItem` из `server/playlist.js` и `cleanDeck` из
  `server/decks.js`; проверить: неизвестный тип → null, countdown без даты → null, плохой id заменяется новым,
  лишние поля выбрасываются, `duration` ограничена 3…3600.

Если тест находит настоящую ошибку — **не чини молча**: опиши её владельцу и спроси, исправлять ли в этой задаче.

## Не трогать

Поведение функций. Только экспорт для тестов, если его не было. `tests/` не должна попадать в архивы `pack.mjs`
(проверь список в tools/pack.mjs).

## Проверка

`npm test` зелёный; специально сломать одну проверку (например, `t < b.end` → `t <= b.end`) — тест падает, вернуть.

Работай по CLAUDE.md, версия — следующая `v0.8.x`. В CLAUDE.md: в «Порядок работы» после `npm run build` — шаг
`npm test`; в «Архитектуру» — строка про `tests/`. README не меняется.
