# Задача 13. Пароль на редактор

Сейчас редактор `/admin` открывается с любого компьютера школьной сети, включая компьютерные классы. Нужен простой
пароль, чтобы ученики не могли менять расписание и плейлист. Экраны (`/`) работают без пароля, как раньше.

## Как должно работать

- Пока пароль не задан — всё как сейчас (никаких окон входа). В редакторе, в шапке (`AdminApp.vue`), кнопка
  «🔒 Пароль»: задать / сменить / убрать пароль (для смены и снятия — ввести текущий).
- Пароль задан → открывая `/admin`, человек видит окно «Вход в редактор» (поле пароля + «Войти»). После входа браузер
  помнит вход 30 дней (cookie). Кнопка «Выйти» в шапке.
- Без входа **сервер отклоняет все записи** ответом 401: PUT /api/data, /api/playlist, /api/decks, /api/backup*,
  POST/PATCH/DELETE /api/media*, восстановление копий. Чтение (GET) открыто — экраны его используют.
  Без пароля остаются: POST /api/screens (отчёты экранов) и POST /api/decks/<id>/take (экраны берут карточку).
- Редактор при ответе 401 показывает окно входа, не теряя несохранённую правку (повторить запрос после входа).
- Забыли пароль — удалить файл `data/auth.json` на сервере (написать это в README и мелко под окном входа:
  «Забыли пароль? Обратитесь к администратору табло»).

## Как сделать (сервер без зависимостей — только `node:crypto`)

- `server/auth.js`: пароль хранится как `scrypt`-хэш с солью в `data/auth.json` `{ salt, hash }`; сессии —
  случайные токены (32 байта hex) в `data/sessions.json` `{ token: expiresAt }` (переживают перезапуск сервера).
  API: `GET /api/auth` → `{ required, loggedIn }`; `POST /api/auth/login { password }` → cookie
  `tablo_session=…; HttpOnly; SameSite=Strict; Path=/; Max-Age=2592000`; `POST /api/auth/logout`;
  `PUT /api/auth/password { current, next }` (next пустой — убрать пароль). Сравнение хэшей — `timingSafeEqual`;
  после 5 неверных попыток с одного IP — пауза 1 минута.
- `api.js`: проверка `isAllowed(req)` до делегирования в обработчики — для всех методов кроме GET, кроме двух
  исключений выше. Работает и в `server.js`, и в Vite (общий `api.js`).
- Клиент: загрузка медиа идёт через XHR (`src/admin/mediaApi.js`) — cookie отправится сама (тот же адрес), но
  обработай 401 и там. Запросы `fetch` в store.js / playlist.js / decks.js / BackupPanel — обработать 401
  (общая функция в одном месте, например в store.js: показать окно входа).
- `server/backup.js`: файлы `auth.json` и `sessions.json` **не** класть в снимки и не восстанавливать (`isDataFile`).
- `tools/pack.mjs`: эти файлы в пакет не попадают (там data/ собирается выборочно — проверь).

## Проверка (копия сервера)

Без пароля — всё как раньше; задать пароль → новое окно редактора просит вход, правка без входа даёт 401 и окно
входа; после входа правки сохраняются; экран продолжает работать (отчёты, колоды); перезапуск сервера — вход
сохранился; неверный пароль 5 раз — пауза; «Выйти»; убрать пароль. Проверить `curl -X PUT` без cookie → 401.
