# Этап 12, задача 03. Запасной сервер на втором компьютере

Сейчас всё держится на одном ПК: сломался он — экраны показывают ошибку, пока не восстановят из копии вручную.
Нужен второй ПК с копией табло, который подхватывает экраны, если основной недоступен.

**Перед началом спроси владельца**: есть ли второй постоянно включённый ПК в той же сети, его адрес, и подключены
ли к нему экраны. Без второго ПК задачу не делать.

## Как должно работать

- **Режимы**: основной (как сейчас) и запасной. Запасной задаётся в `server-settings.txt` рядом с server.js
  (формат как kiosk-settings.txt): `role = standby`, `main = http://192.168.1.10:8080`, `key = <общий ключ>`.
  На основном — тот же `key` (ключ генерирует основной в окне «Состояние системы» → «Запасной сервер»).
- **Синхронизация** (запасной тянет с основного раз в 5 мин):
  - `GET /api/sync/manifest` на основном → список файлов data/ (кроме sessions.json, служебных) и media/ с размером и
    временем изменения; доступ только с заголовком `X-Sync-Key` (не по паролю пользователя);
  - `GET /api/sync/file?path=…` — файл (путь строго из манифеста, без `..`);
  - запасной докачивает новые/изменённые файлы (во временный .part → rename), удаляет пропавшие из media/ только
    после 3 синхронизаций подряд без них (защита от сбоя).
  - пользователи (users.json) синхронизируются, чтобы на запасном можно было войти, но пароль ключа синхронизации в
    данные не попадает.
- **Запасной — только для показа**: редактор на нём открывается с красной плашкой «Это запасной сервер: правки здесь
  не сохраняются» и все записи → 403. Так не будет двух разных версий данных.
- **Переключение экранов**: экран знает адрес запасного (основной отдаёт его в SSE `hello`). Экран без связи с
  основным больше 2 минут → переходит на тот же путь запасного (`location.replace`, имя экрана `?name=` сохранить);
  на запасном — раз в минуту проверяет основной и возвращается, когда тот снова отвечает 2 минуты подряд.
  Экран, который работает на самом основном ПК (`localhost`), при отказе ПК погаснет вместе с ним — так и написать
  в README.
- Окно «Состояние системы» на основном: «Запасной сервер: последняя синхронизация 10:35, отстаёт на 0 файлов» / «не
  отвечает с 9:00».

## Данные

`server-settings.txt` — не в git и не в архиве обновления (как kiosk-settings.txt); в архиве установки — образец с
комментариями. Синхронизационные API добавить в `isAllowed` как исключение с собственной проверкой ключа.

## Проверка

Две копии сервера на 8090 (основной) и 8091 (запасной) с разными папками; запасной догоняет данные и картинки за
один цикл (для теста — интервал из параметра); правка на основном → через цикл на запасном; запись на запасном → 403;
экран на 8090: остановить основной → через 2 мин экран на 8091 с тем же `?name`; запустить основной → вернулся.
Неверный ключ → 403, `path=../data/users.json` → 400.

«Архитектуре». README: «Запасной сервер».
