# Этап 9, задача 05. Личные учётные записи и права на разделы

Сейчас пароль один на всех (server/auth.js, data/auth.json). Нужны личные входы: знать, кто правит (для журнала,
задача 06), и давать людям только нужные разделы — завуч правит расписание, пресс-центр — новости и фото.

## Как должно работать

- **Пользователь**: имя для людей («Иванова И. И.»), логин (латиница/цифры, 3–30), пароль (4–100), права, признак
  «отключён».
- **Права** — галочки (не жёсткие роли):
  - «Расписание» — PUT `/api/data` (расписание, изменения, звонки, настройки табло);
  - «Плейлист» — PUT `/api/playlist` (слайды, бегущая строка, гашение, срочный режим);
  - «Колоды» — PUT `/api/decks`;
  - «Медиатека» — POST/PATCH/DELETE `/api/media*`;
  - «Администратор» — всё перечисленное + резервные копии `/api/backup*` + пользователи + прочие служебные записи.
- **Вход**: окно — логин + пароль (вместо одного пароля). В шапке: «Иванова И. И. · Мой пароль · Выйти».
- **Раздел без прав**: виден только для чтения — сверху серая плашка «Вы можете только смотреть этот раздел», поля
  неактивны (по образцу `ui.readonly` экрана, но в редакторе); сервер всё равно отклонит запись — **403**, а не 401
  (401 — «войдите», 403 — «нет прав»: окно входа на 403 не показывать, показать сообщение «Нет прав на этот раздел»).
- **Окно «Пользователи»** (только «Администратор», кнопка в шапке вместо «🔒 Пароль»): список, добавить, имя, логин,
  права, «Задать новый пароль», «Отключить», «Удалить» (подтверждение). Нельзя удалить или отключить себя и
  последнего администратора, нельзя снять с себя «Администратора», если других нет.
- Сменили пароль или отключили пользователя — его входы на всех компьютерах завершаются.
- **Нет ни одного пользователя** — как сейчас без пароля: всё открыто, в шапке «🔒 Создать администратора».

## Данные и сервер

- `data/users.json`: `{ users: [{ id, name, login, salt, hash, rights: [], disabled }] }`.
- `data/sessions.json`: `{ токен: { exp, user } }`. Старый формат (`токен: число`) — считать недействительным.
- **Переход со старого пароля**: есть `auth.json`, нет `users.json` → при старте создать пользователя «Администратор»,
  логин `admin`, с тем же salt/hash и всеми правами; `auth.json` переименовать в `auth.json.old`. В README:
  «войдите логином admin со старым паролем».
- `isAllowed(req)` → `{ ok, code }` (или две функции): GET открыт (кроме того, что задачами закрыто явно), исключения
  экранов остаются (POST /api/screens, POST /api/decks/<id>/take), запись — нужное право по адресу. Таблица
  «адрес → право» — одна, в server/auth.js, с комментарием.
- API: `GET /api/auth` → `{ required, user: { id, name, rights } | null }`; `POST /api/auth/login { login, password }`;
  `PUT /api/auth/password { current, next }` (свой); `GET/POST/PUT/DELETE /api/users*` (администратор), в ответах
  **без** salt/hash.
- Ограничение 5 неверных попыток — по IP и по логину.
- users.json — как auth.json: не в снимках копий (`isDataFile`), не в архивах pack.mjs.
- Клиент: `admin/auth.js` — текущий пользователь и `can(right)`; AuthModals.vue — новое окно входа; разделы
  AdminApp читают `can()`.
- Забыли пароль администратора: удалить `data/users.json` на сервере → открытый режим, создать заново (README и
  мелко под окном входа, как сейчас).

## Проверка (копия сервера)

Переход со старым auth.json → вход admin; создать «Завуч» (только Расписание) и «Пресс-центр» (Плейлист, Медиатека);
под завучем: правка расписания сохраняется, плейлист только для чтения, прямой PUT `/api/playlist` → 403; под
