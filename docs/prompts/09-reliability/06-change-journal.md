# Этап 9, задача 06. Журнал правок с откатом

Нужно видеть, кто, когда и что поменял, и вернуть отдельную правку («верни расписание 9Б, как было вчера утром»),
не трогая остальное. Нужны задачи 03 (`src/dataDiff.js`) и 05 (пользователи). Если их нет — остановись и скажи
владельцу.

## Как должно работать

- В шапке редактора кнопка «Журнал» (видна всем вошедшим). Окно / раздел — лента записей, новые сверху:
  «14.10 18:05 · Иванова И. И. · Расписание · 8А, вторник: 2 урока; Изменения: 3 строки».
  Фильтры: раздел (Расписание / Плейлист / Колоды / Медиатека / Пользователи и копии), человек, день.
  Подгрузка по 50 («Показать ещё»).
- У записи: «Подробнее» (полный список отличий из dataDiff) и «Вернуть как было до этой правки» (только у того, у кого
  есть право на этот раздел) → подтверждение «Расписание вернётся к состоянию на 14.10 18:03. Правки, сделанные
  после, тоже пропадут: …(список более поздних записей этого раздела)» → откат. Откат сам пишется в журнал
  («Откат к 14.10 18:03»), и его тоже можно откатить.
- Медиатека: «добавлен файл», «удалён файл», «переименован» — без отката (удалённый файл вернуть можно только из
  резервной копии — так и написать).
- Служебное: вход/выход, смена пароля, пользователи, резервные копии и восстановление — пишутся без подробностей.

## Как записывать (сервер)

- **Группировка**: при правке ячеек PUT идёт каждые 300 мс. Записи одного человека в один файл с паузами меньше
  2 минут — **одна** запись журнала (обновляется её время конца и список отличий от начала группы).
- **История версий**: перед первой записью группы сервер сохраняет прежний файл в
  `data/history/<schedule|playlist|decks>/<время>.json`. Хранить 60 дней, но не меньше последних 50 версий на файл
  (чистка раз в сутки и при старте).
- Журнал: `data/journal/<ГГГГ-ММ>.json` — `{ items: [{ id, at, until, user, name, ip, area, summary: [строки],
  version? /* имя файла истории */ }] }`, атомарная запись. `summary` считает сервер через `src/dataDiff.js`
  (общий модуль — добавить его в pack.mjs и в копию сервера для тестов, как deckText.js).
- API: `GET /api/journal?area=&user=&before=` (только после входа — впиши в isAllowed),
  `POST /api/journal/<id>/revert` (право на раздел записи). Откат ставит свежий updatedAt (иначе экраны не загрузят)
  и шлёт обычное SSE.
- Пишут в журнал все места записи: api.js (schedule), server/playlist.js, server/decks.js, server/media.js
  (в том числе `removeMediaFromPlaylist`/`removeMediaFromDecks` — отметка «из-за удаления файла»), server/backup.js
  (restore), server/auth.js. Одна функция `logChange(req, area, before, after)` в новом `server/journal.js`.
- `data/history/` и `data/journal/` в снимки копий не входят (снимки — только json в корне data/, проверь) и в
  архивы pack.mjs тоже.

## Проверка (копия сервера)

Под двумя пользователями: правки расписания подряд — одна запись; через 3 мин — вторая; откат первой — ячейки
вернулись, экран обновился, в журнале запись об откате; откат отката; плейлист — удалить слайд, откатить — слайд
вернулся; удалить файл медиатеки — две записи (медиатека и плейлист), откат плейлиста возвращает слайд без файла —
экран его пропускает (проверить, что не падает). Пользователь без права «Расписание» не видит кнопку отката у записей
расписания. 1280 px — окно журнала читается.
