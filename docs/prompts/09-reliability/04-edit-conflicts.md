# Этап 9, задача 04. Два человека правят одновременно — правки не теряются

Расписание, плейлист и колоды сохраняются целиком (PUT всего файла). Если завуч правит 8А, а в это же время
другой учитель правит 6Б, последний сохранивший затирает правку первого: его клиент ещё не успел загрузить свежие
данные. Нужно, чтобы сервер не принимал запись «поверх» неизвестной ему версии, а клиент объединял правки.

## Как должно работать

- Каждый стор (`src/store.js`, `src/playlist.js`, `src/decks.js`) помнит **базу** — копию данных, которую он
  последним загрузил или успешно сохранил, — и её `updatedAt`.
- PUT отправляет заголовок `X-Base-Updated: <updatedAt базы>`. Сервер (api.js для schedule, server/playlist.js,
  server/decks.js): если `updatedAt` в файле больше базы — ответ **409** `{ conflict: true, current: <данные> }`,
  файл не меняется. Нет заголовка — пишет как раньше (старые вкладки, совместимость).
- Клиент на 409 делает **трёхстороннее объединение**: `merge3(base, mine, theirs)` — чистая функция в
  `src/merge.js`:
  - объекты — по ключам; массивы объектов с `id` (слайды, колоды, карточки, объявления бегущей строки) — по id,
    порядок — из theirs, новые свои — на своих местах;
  - прочие массивы (уроки `[{s, r}]`, строки изменений) — поэлементно по индексу;
  - если одно и то же место поменяли оба по-разному — **побеждает своя правка** (человек сейчас её видит), такое
    место записывается в `conflicts`.
  Затем повторный PUT с новой базой = theirs. Три 409 подряд — остановиться, показать ошибку «Не удаётся сохранить:
  данные меняются слишком часто, обновите страницу».
- Если `conflicts` не пуст — плашка в шапке на 10 с: «Одновременно с вами эти же места правил кто-то ещё
  (8А, вторник, 3 урок) — оставлена ваша правка». Без конфликтов — молча.
- SSE-обновление, пришедшее, пока есть несохранённые свои правки (идёт debounce 300 мс), тоже объединять через
  merge3, а не затирать локальное.

## Данные

Формат файлов не меняется. Тесты `tests/merge.test.js`: две непересекающиеся правки расписания; оба поменяли одну
ячейку; удалён слайд у одного и изменён у другого (вернуть изменённый — правка важнее удаления; описать в
комментарии); добавлены разные слайды.

## Проверка (копия сервера)

Два контекста Playwright, оба в редакторе: в первом печатать в 8А, во втором одновременно в 6Б — после паузы обе
правки в файле и в обоих окнах. Одна и та же ячейка — остаётся правка того, кто сохранил вторым, у него плашка.
Экран (третье окно) показывает итог.
