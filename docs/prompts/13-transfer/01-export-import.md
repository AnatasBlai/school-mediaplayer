# Этап 13, задача 01. Перенос плейлиста одним файлом: «Сохранить в файл» и «Загрузить из файла»

Владелец правит табло дома, на своей копии табло (установлена из архива pack.bat, `start.bat`), а в школе редактор
с домашнего ПК недоступен. Нужно унести правки на флешке **одним файлом**: плейлист вместе со всеми фото и видео, по
желанию — колоды и расписание. В школе файл загружается в редакторе, и экраны переходят на новый плейлист.

## Как пользоваться (так описать в README)

1. Первый раз: в школе «Сохранить в файл» со всеми галочками → дома «Загрузить из файла» → «Заменить целиком».
   Так домашняя копия начинает с тех же данных и тех же файлов медиатеки.
2. Дома правите, «Сохранить в файл».
3. В школе «Загрузить из файла» → смотрите, что изменится → «Заменить целиком» или «Добавить новые слайды».

## Где в редакторе

В разделе «Плейлист», в левой колонке под «Настройки экрана», блок «Перенос на другой компьютер» с двумя кнопками:
«Сохранить в файл» и «Загрузить из файла». Тот же пункт есть в меню ⚙ шапки (HeaderMenu).

## Выгрузка («Сохранить в файл»)

- Окно с галочками:
  - «Плейлист: слайды, бегущая строка, гашение, свои шаблоны» — всегда, неактивная галочка;
  - «Колоды» (по умолчанию — вкл., если в плейлисте есть слайды-колоды);
  - «Расписание, изменения и звонки» (по умолчанию выкл.);
  - «Все файлы медиатеки, а не только те, что в слайдах» (по умолчанию выкл.).
  Именинники в файл **не попадают** никогда (личные данные).
- Под галочками: «В файл попадёт: 23 слайда, 3 колоды, 41 файл (1,2 ГБ)». Считает сервер по тем же правилам, что
  и выгрузка, пересчитывается при смене галочек.
- Больше 4 ГБ — кнопка неактивна, надпись «Больше 4 ГБ: такой файл не поместится на флешку FAT32. Уберите лишние
  видео или снимите „Все файлы медиатеки“».
- «Скачать» — обычная загрузка браузером (ссылка `<a download>` на GET), имя `tablo-ГГГГ-ММ-ДД_ЧЧ-ММ.zip`.
  Браузер сам показывает ход и спрашивает, куда сохранить.
- Какие файлы медиатеки нужны: `media` у слайдов и у своих шаблонов, при включённых колодах — `media` у карточек.
  Превью (`thumb`) — вместе с файлами.

## Загрузка («Загрузить из файла»)

1. Выбор `.zip` → отправка на сервер с полосой хода (XHR потоком, как `uploadMedia` в admin/mediaApi.js, с
   `needLogin()`). Не наш файл (нет `manifest.json` нужного формата) или битый архив → «Это не файл табло или файл
   повреждён», ничего не меняется.
2. **Предпросмотр** (сервер разобрал архив, но ещё ничего не применил):
   - откуда файл: «Сохранён 20.10 21:30 на компьютере HOME-PC, версия табло 0.13.0»; файл из более новой версии —
     жёлтое «Файл из более новой версии табло: N слайдов этой версией не поддерживаются и будут пропущены» (их
     выбрасывает `cleanItem` — посчитать заранее);
   - **Плейлист** — переключатель «Заменить целиком» / «Добавить новые слайды» и список отличий для выбранного режима
     (`diffPlaylist` из src/dataDiff.js; для «Добавить» — «добавятся: …», «обновятся (тот же слайд): …»);
     в файле включён срочный режим — красное «В файле включён срочный режим „…“» (при «Заменить целиком»);
   - **Колоды** (если есть в файле) — галочка + `diffDecks`; **Расписание** (если есть) — галочка, по умолчанию
     **выкл.**, + `diffSchedule` и предупреждение «Расписание, изменения и звонки заменятся целиком»;
   - **Файлы**: «новых файлов: 5 (320 МБ), уже есть в медиатеке: 12»; не хватает места на диске (запас 500 МБ) —
     красное, кнопка «Загрузить» неактивна.
   - Галочки разделов, на которые у пользователя нет права (`can()`), неактивны с подписью «нет прав».
3. «Загрузить» → полоса хода копирования файлов → «Готово: плейлист заменён, добавлено 5 файлов». Экраны
   обновляются сами.
4. «Отмена» или закрытое окно → временный файл удаляется. Брошенные временные файлы сервер удаляет через 1 ч и при
   старте.

## Как применять (сервер)

- **Файлы медиатеки**, для каждого файла из архива:
  - такой же файл уже есть (совпали размер и SHA-1) → берётся существующий id, файл не копируется;
  - id свободен → файл копируется под тем же id;
  - id занят другим файлом → новый id (как в `upload` в server/media.js).
  Копирование потоком из архива во временный `.part` → rename (как `saveBody`), запись в media.json с названием,
  категорией, размерами, длительностью и превью из архива. SHA-1 существующих файлов считать лениво и запоминать в
  media.json полем `sha1` (новое поле → server/media.js, раздел «Данные» CLAUDE.md; клиенту оно не нужно).
- **Перестановка id**: все ссылки `media` в слайдах, шаблонах и карточках колод переписываются по таблице старый →
  новый id. Это чистая функция `remapMedia(data, map)` в новом `src/transfer.js` (без Vue), с тестом.
- **Плейлист**:
  - «Заменить целиком» — весь playlist.json из файла через обычную очистку (`cleanItem`, `cleanTemplates`,
    `cleanTicker`, `cleanBlank`, `cleanUrgent` — найди общую функцию очистки в server/playlist.js, не дублируй её);
  - «Добавить новые слайды» — слайды из файла: тот же id есть → заменить на месте, нет → в конец очереди; свои шаблоны
    — так же по id; объявления бегущей строки с новым текстом — в конец (≤10, лишние не добавлять и сказать об этом
    в итоге); шаблон экрана, гашение и срочный режим — школьные, не трогать.
- **Колоды** — по id: есть → заменить, нет → добавить. Школьные колоды, которых нет в файле, не удаляются (в обоих
  режимах). Через `cleanDeck`.
- **Расписание** — schedule.json из файла целиком, через ту же нормализацию, что и при PUT `/api/data`.
- Каждый изменённый файл данных получает свежий `updatedAt` (`nextUpdated` из server/conflict.js), сервер шлёт
  обычное SSE (`playlist`/`decks`/`data`/`media`). В журнал: `logChange(req, area, before, after)` для каждого
  раздела (так загрузку можно откатить из «Журнала правок») и `logEvent(req, 'media', 'Загружено из файла: 5 файлов')`.
  Подпись записей — «Загружено из файла tablo-….zip».
- Применение — целиком или никак: сначала скопировать все нужные файлы медиатеки; ошибка при копировании → удалить
  уже скопированные в этой загрузке, данные не менять, ответить ошибкой.

## Формат файла

ZIP. Внутри:
```
manifest.json   { format: 'tablo-transfer', version: 1, app: '0.13.0', createdAt, host /* os.hostname() */,
                  parts: ['playlist', 'decks'?, 'schedule'?],
                  media: [{ id, file, type, name, category, size, w, h, duration, sha1, thumb }] }
playlist.json   decks.json?   schedule.json?
media/<file>    media/thumbs/<id>.jpg
```
- Свой модуль `server/zip.js` **без зависимостей**:
  - запись потоком: метод 0 (без сжатия: фото и видео уже сжаты), флаг UTF-8 в именах (бит 11, см. «Подводные
    камни» про tar.exe), CRC-32 своей таблицей (`zlib.crc32` есть не во всех версиях Node), data descriptor, чтобы
    не держать файлы в памяти. Без Zip64: общий размер ограничен 4 ГБ (проверка до начала выгрузки);
  - чтение: End of Central Directory → центральный каталог, методы 0 и 8 (`zlib.createInflateRaw`), чтобы читался
    и архив, пересжатый архиватором; проверка CRC при извлечении.
  - **Безопасность**: из архива берутся только ожидаемые имена (`manifest.json`, три json, `media/<id>.<расширение
    из списка медиатеки>`, `media/thumbs/<id>.jpg`); всё прочее, `..`, абсолютные пути и `\` — игнорировать или
    отклонять архив. Размер распакованного json — не больше 20 МБ.
- Тест `tests/zip.test.js`: CRC-32 строки «123456789» = `cbf43926`; запись → чтение (кириллица в имени, пустой
  файл, файл 5 МБ); архив с `../evil.txt` отклоняется; обрезанный архив → понятная ошибка. Тестам писать только во
  временную папку `os.tmpdir()`.

## API (новый `server/transfer.js`, подключить в api.js)

- `GET /api/transfer/estimate?parts=decks,schedule&all=1` → `{ slides, decks, files, bytes, tooBig }`;
- `GET /api/transfer/export?parts=…&all=…` → поток zip (`Content-Disposition: attachment`, имя с датой);
- `POST /api/transfer/import` — тело = файл потоком (без multipart) → временный файл `data/transfer/<token>.zip`,
  разбор → `{ token, manifest, preview }`;
- `POST /api/transfer/import/<token>/apply { playlistMode: 'replace'|'add', decks: bool, schedule: bool }`;
- `DELETE /api/transfer/import/<token>`.
- Права (server/auth.js): GET export/estimate — вошедший с правом «Плейлист» (+ «Расписание», если в parts
  schedule, + «Колоды», если decks; проверку частей делает transfer.js через `can`); в `rightFor` эти GET — не
  открытые. Запись: в `WRITE_RIGHTS` — `'login'`, а права на разделы проверяет transfer.js: плейлист — «Плейлист» и
  «Медиатека», колоды — «Колоды», расписание — «Расписание». Нет права → 403.
- `data/transfer/` — служебная папка: не в снимках копий, не в архивах pack.mjs, не в «Объёме data» окна
  «Состояние» (или отдельной строкой).
- Под Vite (dev) тоже работает (общий api.js).

## Не трогать

Формат playlist.json, decks.json, schedule.json. Обычную загрузку файлов в медиатеку. Именинники, пользователи,
доступ, журнал и прочие служебные файлы в архив не попадают ни при каких галочках.

## Проверка

Две изолированные копии сервера: «дом» (8090) и «школа» (8091), разные `data/` и `media/`, в обеих пользователи.
- Дома: новость с фото, слайд с видео (WebM, см. «Подводные камни»), колода с картинкой у карточки, свой шаблон;
  выгрузить со всеми галочками. Открыть архив .NET ZipFile в PowerShell — читается, русские имена целы.
- В школе «Заменить целиком»: слайды, шаблоны, колоды на месте, файлы открываются, экран (окно `/`) переключился
  (журнал `.slide.active`), в журнале правок — записи, откат возвращает старый плейлист.
- «Добавить новые слайды»: школьные слайды остались, новые в конце, совпавший по id обновился, гашение не изменилось.
- Один и тот же файл в обеих медиатеках → не задвоился. Совпал id, но файлы разные → новый id, слайд показывает
  правильную картинку.
- Подложить обрезанный zip, чужой zip, zip с `../` → ошибка, данные и media/ не изменились.
- Пользователь без права «Колоды»: галочка колод неактивна, прямой apply с `decks: true` → 403.
- Большой файл (сгенерировать фиктивное «видео» на 300 МБ): выгрузка и загрузка идут потоком — память процесса
  node заметно не растёт (замерить `process.memoryUsage().rss` до и после).
- 1280 px: окна выгрузки и загрузки читаются, полоса хода видна.
